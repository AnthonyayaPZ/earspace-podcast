# 句子整理、同步循环与历史文稿重建

本功能只处理已有文本和时间戳，在普通 CPU 上执行，不调用大模型／云端语音 API，也不重新编码或下载音频。没有字幕的节目仍需先导入文稿或使用语音识别；本次不包含云端 ASR 接入。

## 处理流程

1. `transcripts.segments` 保存原始字幕片段。新下载的 JSON3 另外保留可用的 `tOffsetMs`，作为片段内词／文本块的开始时间。手动导入和旧数据库无需改变格式。
2. 校验有限非负时间、非空文本和节目时长；异常片段只在句子视图中略过并计数，原始来源保留。按开始时间稳定排序。仅合并同一开始时间、前缀包含的滚动修订，保留相邻时间的真实重复发言；不凭相同文字删除字幕。
3. 将重叠字幕的显示尾部截到下一片段的开始，避免一秒多的显示重叠带入循环。优先使用字幕词级偏移，否则按片段内各词的字符权重分配时间，得到单调、不重叠的文本时间映射。
4. 拼接文本，英文单词之间补空格，连续汉字之间不插入空格。识别 `.!?。！？` 及右引号／括号，保护 `Dr.`、`Mr.`、`e.g.`、`U.S.`、姓名首字母、小数和句内省略号。跨片段合并一句；同一片段内的多句话拆开；不改写措辞，不补造标点。
5. 没有可靠句末标点时，1.5 秒以上的片段间停顿可以结束一个语段；超过 45 秒或中英文分别 240／800 字符时在已有词／字边界截断，剩余部分继续处理。此类内容标为 `fragment`，界面显示未完整断句数，不把长度切分称为完整句子。手动文稿保留原有片段边界，同时仍可拆开片段内多句。
6. 根据同一映射生成句子的 `start/end`，并返回来源、切分原因和时间精度。TXT、VTT、点击跳转、高亮、循环全部消费这个版本。

例：`There has been a lot of` + `misinformation about` + `AI.` → `There has been a lot of misinformation about AI.`。`This is Andrew. He was` 的后半段继续与后面的 `the co-founder of Google` 等合并。

实现以文本长度为主，排序字幕和边界事件约为 O(n log n)，时间索引使用二分查询。缓存命中后不重新断句。片段内分界是估算时会明确返回 `estimated`；采用 JSON3 词级偏移时返回 `caption_words`，它同样不能代替对音频波形的强制对齐。缩写在句末也存在语言歧义；规则断句不保证语法理解和 ASR 内容正确。

## 循环与同步

播放器统一使用半开时间区间 `[start,end)`。二分找到当前句子；静音空隙不继续高亮前一句。勾选循环会选择正在播放的句子，也可点击其他句子更换循环目标。

循环采用按剩余媒体时长／播放倍速计算的短定时器，并用 `timeupdate` 校验；每次唤醒重新读取媒体时钟，达到结束时间后跳回句首。暂停／缓冲停止定时器，恢复播放和改变倍速时重新安排。原生进度条和前后跳转会重新定位循环目标，避免强制拉回旧句子；内部回跳则保留当前目标。最后一句遇到 `ended` 仍会回放，关闭循环后才恢复正常完成记录。

重建后按当前播放位置重新定位，不沿用旧句子序号；音频和视频共用控制器，忽略非当前播放器的事件。关闭播放器或切换节目清空循环。浏览器后台定时节流和音频解码会影响回跳时机，因此不能承诺采样级循环；旧字幕的估算边界也可能带来少量前后偏差。

## 历史数据与重建

启动时新增 `transcript_sentences` 缓存表，不覆盖原表。缓存指纹包含原始 JSON、来源、语言、节目时长和 `sentences-v1` 算法版本。首次读旧文稿自动生成句子视图；网页“重新整理”或 `POST /api/v1/episodes/{id}/transcript/rebuild` 可强制重算。两次结果相同，不会把已经合并过的句子再次作为原始字幕累加处理。

源文稿写入和缓存失效位于同一事务中。读取／重建通过立即事务串行访问，防止导入或 Worker 发布新文稿时留下旧缓存。程序升级需更改算法版本；旧视图将在读取时更新。源文稿可用 `GET .../transcript?view=raw` 随时查看，原始 TXT／VTT 导出加 `view=raw`。

个人数据库、字幕全文、音频、测试报告和备份只保存在本地 `data/`、`artifacts/`，不提交 Git，也不纳入源码发行包。
